# Course Roadmap Experience

## Production architecture

The /courses/:courseId/roadmap route now renders a data-driven roadmap from the published course curriculum and the existing learner progress system.

The roadmap projection is deliberately derived rather than stored as a second copy of the course:

- **Course curriculum:** Course.modules[].lessons[] is the source of truth for node identity, title, lesson type, duration and lesson content.
- **Phase grouping:** Course.roadmap.stages[] supplies the saved phase order, stage title, skills, outcome and lesson assignments.
- **Learner completion:** Progress.completedLessons[] is the source of truth for per-user completed nodes.
- **Protected lesson content:** the inspector loads one lesson at a time through GET /api/courses/:courseId/learn/:itemId. Public visitors receive the course preview only.
- **Progress writes:** completion uses POST /api/progress/:courseId/items/:itemId/complete; reverting a node uses DELETE on that route.

The browser projection is generated by client/src/lib/courseRoadmap.js. Its TypeScript contract is in client/src/lib/courseRoadmap.d.ts, and its JSON Schema is docs/COURSE_ROADMAP_SCHEMA.json.

## Phase generation

New automatically generated roadmaps use four to six balanced, contiguous phases when there are at least four lessons. Smaller courses use one phase per available lesson, avoiding empty phases.

The roadmap schema records whether a phase plan is generated, admin or legacy:

- Automatically generated phase plans can be regenerated when their source curriculum changes or when an older generated plan falls below the new minimum phase count.
- Admin-curated phase assignments are preserved when their source curriculum fingerprint remains valid.
- Legacy phase plans are not silently rewritten just because the grouping algorithm changes.

## Interaction model

- Filters and search operate on the real nodes supplied by the course.
- Core lessons, quizzes/checkpoints, project milestones and the final project capstone have distinct visual treatments.
- Clicking a node opens a keyboard-accessible right-side inspector on desktop and a bottom sheet on mobile.
- Topic checkboxes are local inspector state. Lesson completion is persisted through the existing Progress API.
- Protected video and reference links are requested only when an enrolled learner opens a node.
- Brand colors resolve through the existing --accent, --bfs-ai, --surface, --bg, --border and typography tokens, including dark mode.

No duplicate course-node collection or roadmap-specific progress table is introduced.
